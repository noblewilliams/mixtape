# P2.5 — Local preview audio analysis (feature-coverage lift)

**Why:** features coverage is 59.9% (< the 80% gate; see decisions.md 2026-08-29/30). ~1,770 tracks had no ReccoBeats match. The DJ's feature-fit term scores on **tempo, energy, valence** (`src/dj/pool.ts`); missing features are unscored-not-excluded, so 40% of the library gets no tempo/energy fit at all.

**What:** a founder-Mac-run CLI (`server/scripts/analyze-previews.ts`, `npm run analyze-previews`) that, for every track with an `apple_id` and no `track_features` row: looks up its iTunes 30s preview (works from residential IPs — Apple 403s only datacenter/Workers IPs, decisions.md 2026-08-29), downloads it, analyzes it locally, and upserts a partial `track_features` row.

## Binding design facts

- `track_features` columns: tempo, key, mode, energy, danceability, valence, acousticness, instrumentalness, liveness, speechiness, loudness (`src/db/schema.ts:65-79`).
- **Honesty rule:** write ONLY what 30s of audio can genuinely yield: `tempo`, `key`, `mode`, `energy`, `danceability`, `loudness`. Leave `valence`, `acousticness`, `instrumentalness`, `liveness`, `speechiness` NULL — no fabricated proxies. (Tempo+energy are 2 of the 3 scored axes; that is the lift.)
- Value ranges must match ReccoBeats' conventions so the two sources are comparable in the same column: energy/danceability in [0,1]; loudness in dB (negative, LUFS-like); tempo in BPM; key 0-11 pitch class; mode 0/1.
- Analysis stack: **essentia.js** (WASM, Node — keeps the toolchain TS-only). Decode m4a→wav via **`afconvert`** (stock macOS, no Homebrew dependency). If the Task-1 spike finds essentia.js unworkable (WASM/loader pain), fall back to `python3 -m venv` + librosa and record the switch in decisions.md — do not fight WASM for more than the spike.
- Preview source: `lookupItunes` (`src/enrich/itunes.ts`) — batch lookups (iTunes `lookup?id=a,b,c` accepts ~200 ids/call), throttled conservatively (≤ ~20 calls/min).
- Write path: direct Drizzle from the script over `.dev.vars` `DATABASE_URL` (retitle-sessions precedent) — no new server surface, nothing to deploy. Upsert must be insert-if-absent only (`ON CONFLICT DO NOTHING` semantics): never overwrite a ReccoBeats row.
- Script conventions (established): `.dev.vars` loader with quote-strip; **dry-run by default, `--apply` to write**; `--limit N` for pilots; per-row try/catch with fixed-string logging (never interpolate DB/SDK error messages — credential-leak lesson); resumable.
- Resume/skip state: a local checkpoint JSON next to the cache dir recording per-apple_id terminal outcomes (`no_hit`, `no_preview`, `analysis_failed`) so reruns skip them; downloaded previews cached on disk and reused. Tracks that gained a `track_features` row are excluded by the DB query itself.
- Downloads/cache live under `~/.cache/mixtape-previews/` (or `MIXTAPE_PREVIEW_CACHE`), never in the repo.

## Tasks

### Task 1: analyzer core + spike (`server/scripts/lib/preview-analyzer.ts`)
- Spike essentia.js in Node first: decode a wav, run RhythmExtractor2013 (tempo), KeyExtractor (key/mode), RMS/energy → [0,1] mapping, Danceability, ReplayGain/loudness. If blocked, invoke the librosa fallback decision.
- `analyzePreview(wavPath) -> {tempo, key, mode, energy, danceability, loudness}` + `decodeToWav(m4aPath)` via afconvert (child_process, fixed-string errors).
- TDD: tests generate WAV fixtures programmatically (click track at a known BPM, a pure tone) — no committed binaries; assert tempo within ±3 BPM, energy of silence ≈ 0 vs tone > 0, key of a synthesized triad. Mark the suite so it skips cleanly on machines without afconvert (CI-safe).
- Commit `feat(scripts): preview analyzer core`.

### Task 2: preview fetcher (`server/scripts/lib/preview-fetcher.ts`)
- Batch `lookupItunes` over chunked apple_ids with throttling; download previewUrl m4a to the cache dir; checkpoint JSON for `no_hit`/`no_preview`; reuse cached files.
- TDD with injected fetch fakes (existing FetchLike seam); no live network in tests.
- Commit `feat(scripts): preview fetcher`.

### Task 3: orchestrator CLI (`server/scripts/analyze-previews.ts` + npm script)
- Query: tracks with `apple_id IS NOT NULL` and no `track_features` row. Pipeline per track: checkpoint-skip → fetch → decode → analyze → upsert (insert-only). Progress lines every N tracks; final summary: analyzed / no_preview / no_hit / failed + resulting features coverage %.
- Flags: dry-run default (prints candidate count + first 10), `--apply`, `--limit N`. Per-row isolation. Re-run converges to zero work.
- TDD: orchestrator over fake fetcher/analyzer/db (PGlite) asserting selection, skip logic, insert-only semantics, resume.
- Commit `feat(scripts): analyze-previews CLI`.

### Task 4: pilot + full run + docs (coordinator-run, founder's Mac)
- `--limit 50 --apply` pilot → spot-check BPMs of well-known tracks against reality; sane ranges.
- Full run; report final coverage. If still < 80%, the GetSongBPM leg (waterfall decision) is the recorded next step — separate decision, not this plan.
- decisions.md entry (what was analyzed, coverage before/after, honesty rule) + README status touch.

## Out of scope (resist)
GetSongBPM integration · valence/mood models · re-analyzing tracks that already have ReccoBeats rows · running analysis on Workers · any client change.
