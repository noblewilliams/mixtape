# Plan: everyone gets a mix

Date: 2026-10-21. Spec: `../specs/2026-10-21-everyone-gets-a-mix-design.md`.
Decisions: pending (five listed at the end of the spec); record them in
`../../decisions.md` when taken.

House cadence: one fresh implementer per task, red tests first, then a
reviewer pass and one fix round. Implementers and reviewers run on Opus at
medium effort. At most two agents in flight. One commit per task, files
staged by explicit path; the drizzle journal is staged with only this
program's entries when another program's migration is in the tree.

## Standing rules for every task

- **Free plan.** 50 subrequests and 10 ms CPU per invocation, 5 cron
  triggers, 10,000 Workers AI neurons a day, Neon 100 CU-hours a month and
  0.5 GB storage. No task assumes a paid limit without a decision.
- **Shared working tree.** Other sessions may hold uncommitted work. Edit
  in place; no stash, checkout, restore or reset; stage by explicit path.
- **No production writes, no deploy, no migration apply** unless a gate says
  the founder runs it. Deploys from a clean worktree of committed HEAD.
- New listener-facing strings and DJ prose have no em dashes; the guard in
  `server/test/dj/no-em-dash.test.ts` covers new exported strings.
- Never store lyric text. Curation tests are golden-set structural
  assertions.
- Docs ride with the change: spec status line per step, `docs/backlog.md`.
- Never run a formatter over a folder; only over files the task created or
  edited.

## Step 1: a fair floor

### Task 1: artist keys

Files: `server/src/db/schema.ts`, new migration (next free number),
new `server/src/dj/artist-keys.ts`, `server/test/dj/artist-keys.test.ts`.

- `artistKey(name)`: lowercase, NFKD then strip combining marks, drop
  everything but letters and digits. `creditedArtists(credit)`: split on
  `&`, `,`, `feat.`, `ft.`, `with`, ` x ` (word-bounded), trim, drop empty.
- `tracks.artist_keys text[]` generated by a Postgres function
  `artist_keys(text)` that mirrors the two helpers (an `unaccent`-free
  `translate` table for the Latin diacritics the catalogue actually holds,
  listed in the test), plus a GIN index. The migration is a function, a
  generated column and an index; check by hand.
- Tests: table-driven pairs ("jay z" / "Jaÿ-Z", "beyoncé" / "beyonce",
  "¥$, kanye west & ty dolla $ign" credits three artists, "drake x future"
  two); the SQL function agrees with the TypeScript helper on the table
  (pglite).

### Task 2: the floor and prompt seeds

Files: `server/src/dj/pool.ts` (`resolvePoolMode`, thresholds),
`server/src/dj/loop.ts` (intent extraction, `INSUFFICIENT_SEEDS_TEXT`),
`server/src/db/schema.ts` (`user_artist_seeds.source` gains `prompt`, a
CHECK or enum change if one exists), `server/test/dj/pool.test.ts`,
`server/test/dj/loop.test.ts`.

- `resolvePoolMode` matches seeds by key against `artist_keys` with the
  GIN index; counts distinct matched seed keys as `seedArtists`.
- Floor: `corpus` when `seedTracks >= 25 && seedArtists >= 2`, or
  `seedTracks >= 40`. Constants `MIN_SEED_TRACKS`, `MIN_SEED_ARTISTS`,
  `SOLO_SEED_TRACKS`.
- The intent extraction returns `namedArtists: string[]` and `namedSongs:
  { title: string; artist?: string }[]`; the loop saves named artists as
  seeds with `source = 'prompt'` before the pool resolves (idempotent on
  the unique key), and keeps named songs on the turn for Task 4.
- New refusal copy without the interview; the no-em-dash guard covers it.
- Tests: the 2026-10-21 golden case (kanye west, jay z, kid cudi against a
  fixture catalogue with "jaÿ-z & kanye west" rows) resolves `corpus`;
  threshold edges; prompt artists become seeds once; the old refusal text
  is gone.

Left open by Task 2's review for later tasks: `buildOutsidePool`'s
`own_artists` match (pool.ts ~1036) still compares exact names; a sixth
named artist fails the whole tool call rather than being cut to five;
`GET /me/artist-seeds` now returns `prompt` rows, which matters once the
artists page prefills; the pinned tool hash in
`outside-picks-flag-off.test.ts` strips the new fields rather than being
re-pinned.

### Gate 1 (founder): migration and deploy

Locale check done 2026-10-21 (read-only): production is PostgreSQL 18.6,
`C.UTF-8` with the built-in locale provider, and `lower()` folds `MØ ŁONA
ΣΑΒΒΑΣ Мумий` correctly, so the SQL keys agree with pglite and with the
TypeScript helper. Catalogue artists carry only Latin diacritics, katakana
and Hangul, all handled. Task 2 still matches seeds in SQL
(`artist_keys && ARRAY[artist_key($seed)]`) so any later drift between the
two helpers cannot break matching.

Gate 1 run, 2026-10-21: migrations 0040 and 0041 applied (journal rows 41
and 42, all 6,438 tracks keyed, "jay z" matches 78 rows), Worker deployed as
`687bc091`. The founder's prompt then failed twice for reasons outside
Step 1, both fixed the same evening:

- `CurationTruncated`: the curation call's budget (1,200 + 80 per track) was
  sized for the JSON alone, but Sonnet 5's adaptive thinking counts against
  `max_tokens`, and a 300-line corpus pool drew more than 4,800 tokens on
  the retry. Raised to 6,000 + 200 per track (`aa8fc98`); the prompt pin in
  `outside-picks-flag-off.test.ts` now hashes the prompt parts apart from
  the budget (`1184696`). Locally the same prompt then returned 15 tracks
  with Jay-Z and Kanye in 49 s.
- `HTTP unknown` after 126 s on production: the model client is built with
  a 60 s timeout and one retry, and that timeout waits for response
  headers, which a non-streaming call does not send until the model has
  finished thinking. Two silent attempts made the 126 s. Fix: stream every
  DJ model call (headers arrive at once) with a 100 s per-call deadline,
  since the iOS client gives up at 120 s (llm.ts).

From a clean worktree: apply the Task 1 migration (a sub-second rewrite of
`tracks`, 6,438 rows, under a brief exclusive lock), deploy, spot-check
`artist_key('MØ ŁONA ΣΑΒΒΑΣ')` on production, then re-run the 2026-10-21
prompt as an anonymous listener and confirm a mix comes back. Delete the
test user through the plugin afterwards.

## Step 2: fill from Apple at prompt time

### Task 3: catalogue client additions

Files: `server/src/musickit/catalog.ts`, `server/test/musickit/catalog.test.ts`.

- `searchArtists(storefront, term, limit)` and `artistTopSongs(storefront,
  artistId, limit)` over Apple's `search` (types `artists`) and
  `artists/{id}/view/top-songs`, same timeout, size cap and token cache as
  the existing calls. Songs come back in the existing `CatalogSong` shape
  with ISRC, duration, genre and release year.
- Tests with recorded fixtures: a hit, no hit, oversized response, 429.

### Task 4: the fill

Files: new `server/src/dj/catalogue-fill.ts`, `server/src/dj/loop.ts`,
`server/src/enrich/runner.ts` (front-of-queue priority),
`server/src/seeds/contracts.ts` (`catalogue_filled`), `server/test/dj/catalogue-fill.test.ts`.

- `fillForSeeds(db, catalog, deps, { userId, storefront, budget })`: for
  each seed key with fewer than `FILL_FLOOR` enriched rows, resolve the
  artist, take `FILL_PER_ARTIST` top songs, insert missing `tracks` rows
  (dedupe by ISRC then Apple id; source `catalogue_fill`), run twin copy,
  then enrich as many as the remaining budget allows through the existing
  `enrichTrack`, counting subrequests per stage. Named songs resolve by
  `searchSongs` and join the same path. Returns `{ inserted, enriched }`.
- The loop calls it only when the mode is `insufficient_seeds` after Task 2
  and the listener is not `personal`, then resolves the mode again.
- Funnel row `catalogue_filled` on the session with the counts.
- Tests: budget respected per stage; nothing in personal mode; twins skip
  enrichment; second resolution sees the rows; a provider 429 leaves the
  rows queued with a failure record and the turn still proceeds.
