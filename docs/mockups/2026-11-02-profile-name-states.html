Profile name: ask once, edit in Account.

A listener's name is Better Auth's user.name. This board covers the three places a listener meets it: one optional first-run page, "What should we call you?", shown once per account after sign-in when no usable name exists; the identity row at the top of iOS Account, which becomes editable; and the name in web Settings › Account, edited inline. Anonymous listeners never see any of it. The grammar, CSS, frames and backgrounds are copied from the approved first-run board (2026-10-20-first-run-flow-states.html, approval approved/2026-10-20-first-run-flow.md); Account follows account_screen.dart and the approved shell; Settings follows AppSettings.tsx and navigation-layout.css. Spec: 2026-11-02-profile-name-design.md. Nothing here is implemented.

Decisions for you (recommendation first; each is drawn below)
  1. Background of the name page: plum black (sign-in). It follows sign-in, so it reads as the last beat of that page rather than a new errand; it needs no seventh image; and it is the darkest of the six, which keeps cream text well above 4.5:1 with the keyboard up. Alternative: violet (Who do you love?), a "question about you" page, but that image belongs to path A, which many of these listeners have just seen. Frames N1 and N9.
  2. Skip: a quiet foot link, "Skip". It is the same place and weight as Step 1's "Skip for now", keeps the one-pill rule, and does not compete with Continue. Not "Skip for now": the page never returns, so "for now" would be untrue; the line already says where the name lives. Alternative: a second outlined pill (N10), louder than an optional question deserves.
  3. Keyboard on arrival: no autofocus. The page is optional; arriving with the keyboard up reads as a demand and hides the image. One tap on the field raises it. Alternative: autofocus saves that tap.
  4. iOS Account edit: inline, in the identity row. The row's title becomes the field in place, with Save and Cancel as text actions under the group, the same pattern as the mix name editor (mix_name_editor.dart). Errors and Retry sit next to what failed. Alternative: a native alert with a text field (A5), which hides the screen, cannot show a failure without closing, and adds a modal for one word.
  5. iOS row affordance: a trailing text action, "Edit" or "Add name". The whole row is the button; the word says what tapping does. No pencil glyph (not a transport symbol) and no chevron (a chevron promises a pushed screen).
  6. Web trigger: an "Edit name" text button before "Manage account". Same quiet wc-text grammar as the rest of Settings; Enter saves and Escape cancels, as in the mix rename. "Add name" when unnamed.
  7. Blank clears without a confirmation. The name is cheap to type again and nothing else depends on it. The hint under the field says so before it happens.
  8. 40 characters is a hard stop. Typing stops at 40, a "34 of 40" count appears from 30, and a pasted longer name is cut with an honest line, "Names stop at 40 characters." The server caps again regardless.
  9. Web unnamed fallback: "Your account", as on iOS. Today web prints an empty title when the name is blank (W-S0).

Open questions
  1. If Skip's own write (the asked flag) fails, the board proceeds anyway and retries the flag silently on the next launch; the page could therefore show once more on that device. Acceptable, or should Skip block until the flag is stored?
  2. Should the name page appear after the Keep this mix sign-in (a listener who has just seen three first-run pages) or wait until their next launch? The spec says after sign-in; drawn that way.
  3. iOS keyboard appearance on graphic pages: drawn dark (keyboardAppearance: Brightness.dark) to match the plum page in both themes. The artist fields today follow the system appearance.
Conflicts found between code and approved records
  1. Avatar shape. The approved shell (Y1 and the record's "Square motif: … the You avatar") draws a square prism tile with the initial. you_tab.dart draws a circle with the initial; account_screen.dart draws a square with no initial. This board draws both as the code does and does not resolve it; a name change updates the You initial.
  2. Web blank name. AppSettings.tsx renders {userName} raw, so an account with no name shows an empty title line, while iOS shows "Your account". Decision 9 fixes it.
  3. Web text-button size. .wc-text is 44 px tall for every pointer (web-controls.css), against the web rule of about 28 px visual height with 44 px only for coarse pointers. Frames here draw 28 px on wide and 44 px at 390; the existing buttons in the same rows would need the same change to match.
  4. Web secondary text contrast. .setting-row small uses --muted #8a838b, about 3.1:1 on the #e9e8e3 plane. The approved navigation board uses #675f68 (about 5:1); frames here use the board's value.
  5. Web field size on first-run pages. The web rule says inputs at 14 px or less; the shipped first-run fields are 16 px (first-run.css), which also stops Safari on iPhone zooming on focus. The name page keeps 16 px with the first-run pages; the Settings field is 14 px.

5 · Validation

Rules from the spec, enforced the same way on every surface and again by the server (databaseHooks.user): trim, collapse inner whitespace, no control characters, 1 to 40 characters. Blank removes the name. Listener counts as no name. The client stops input at 40 and shows a count from 30, so the server cap is never the first thing a listener meets.

InputWhat happens
" Ada Okafor "Saved as "Ada Okafor". The field shows what was typed until Save; the row shows the saved value.
Only spacesName page: Continue stays dimmed. Account and Settings: treated as blank, so Save removes the name.
BlankRemoves the name; the row reads "Your account". On the name page blank cannot be submitted; Skip is the way past.
41+ characters pastedCut to 40 in the field with "Names stop at 40 characters."; the server cuts again if a client does not.
Control characters, line breaksStripped on input (a pasted line break becomes a space); never an error message.
"Listener"Allowed if typed (it is a name), but an account whose name is the anonymous default still counts as unnamed for the prompt.

7 · Note: the DJ using the name

No UI changes. One example of the rule "at most once in a conversation, never as a greeting on every turn": the name lands mid-sentence in the first reply and not again.

8 · Coverage

  • The name page on iOS (390 pt) and web (1240 and 390): empty, typing with the keyboard, saving, save failed, the 40-character cap, 200% text; its background, Skip as a foot link, no autofocus. Light and dark are the same page.
